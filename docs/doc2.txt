1.1 High-Level System Topology

The system is composed of three independently running processes that communicate over a local network:



▸ BACKEND PROCESS (FastAPI + Bot Engine): The Python trading engine runs continuously during market hours. It handles AngelOne SmartAPI communication, all trading logic, and exposes a REST + WebSocket API on localhost:8000.



▸ FRONTEND PROCESS (React + Vite): A Node.js dev server (or Nginx-served build) runs the React dashboard on localhost:5173. It communicates exclusively with the FastAPI backend — never directly with AngelOne.



▸ EMAIL SERVICE (SMTP/Gmail): The backend sends outbound emails via SMTP. No separate process needed — emails are sent from the bot engine itself using Python's smtplib or aiosmtplib.

2. Backend Architecture — FastAPI + Bot Engine

The backend is a single Python application that runs two concurrent responsibilities: the trading bot engine (all market logic) and a FastAPI web server (REST + WebSocket API for the frontend). Both run within the same asyncio event loop — no inter-process communication needed.



2.1 Process Architecture

# main.py — single entry point

async def main():

    app   = create_fastapi_app()   # REST + WebSocket server

    bot   = BotEngine()            # Trading logic

    email = EmailService()         # Alert dispatcher



    # Both run concurrently in the same event loop

    await asyncio.gather(

        uvicorn.serve(app, host='0.0.0.0', port=8000),

        bot.run(),

        email.run_queue_worker(),

    )

2.4.3 WebSocket Manager

class WSManager:

    connections: List[WebSocket] = []



    async def connect(self, ws: WebSocket):

        await ws.accept()

        self.connections.append(ws)



    async def broadcast(self, event_type: str, payload: dict):

        msg = json.dumps({ 'event': event_type, 'data': payload,

                           'ts': datetime.now().isoformat() })

        dead = []

        for ws in self.connections:

            try:

                await ws.send_text(msg)

            except:

                dead.append(ws)

        for ws in dead:

            self.connections.remove(ws)

3.5 WebSocket Client Hook

// hooks/useWebSocket.ts

export function useWebSocket() {

  const store = useBotStore()

  const wsRef = useRef<WebSocket | null>(null)



  const connect = useCallback(() => {

    const token = import.meta.env.VITE_DASHBOARD_TOKEN

    const ws = new WebSocket(`ws://localhost:8000/ws/live?token=${token}`)



    ws.onmessage = (event) => {

      const { event: type, data } = JSON.parse(event.data)

      switch (type) {

        case 'POSITION_UPDATE':   store.onPositionUpdate(data); break

        case 'TRADE_ENTRY':       store.onTradeEntry(data);     break

        case 'TRADE_EXIT':        store.onTradeExit(data);      break

        case 'SIGNAL_DETECTED':   store.onSignalDetected(data); break

        case 'CHAIN_UPDATE':      store.onChainUpdate(data);    break

        case 'RISK_BUDGET_UPDATE':store.onRiskUpdate(data);     break

      }

    }



    ws.onclose = () => setTimeout(connect, 2000)  // auto-reconnect

    wsRef.current = ws

  }, [])



  useEffect(() => { connect(); return () => wsRef.current?.close() }, [])

}

4. Email Alert System — SMTP with HTML Templates

The email alert system replaces Telegram entirely. It uses Python's aiosmtplib for async SMTP delivery and Jinja2 for rich HTML email templates. All emails are sent from a personal Gmail account using App Password authentication.



4.1 Email Service Architecture

Item

Description

SMTP Library

aiosmtplib — async SMTP client compatible with asyncio. Non-blocking; never delays trading logic.

Email Provider

Gmail SMTP (smtp.gmail.com:587 with STARTTLS). Use a dedicated Gmail account for the bot.

Authentication

Gmail App Password (not the account password). Generated in Google Account → Security → App Passwords.

Template Engine

Jinja2 — renders HTML email templates with dynamic trade data.

Queue

asyncio.Queue — all email send requests are queued and processed by a background worker. Prevents email I/O from blocking trading.

Rate Limiting

Maximum 10 emails per hour to avoid Gmail sending limits.

Recipient

Single personal email address from .env. No multi-user overhead.

From Address

bot@gmail.com (your dedicated bot Gmail) — keeps alerts separate from personal inbox.



4.2 Email Service Class

# alerts/email_service.py

class EmailService:

    def __init__(self, settings: Settings):

        self.smtp_host     = 'smtp.gmail.com'

        self.smtp_port     = 587

        self.username      = settings.GMAIL_USER        # bot account

        self.password      = settings.GMAIL_APP_PASS    # App Password

        self.recipient     = settings.ALERT_EMAIL       # your personal email

        self.queue         = asyncio.Queue()

        self.rate_limiter  = RateLimiter(max=10, window_secs=3600)



    async def send(self, template: str, subject: str, context: dict):

        '''Queue an email — non-blocking for caller'''

        await self.queue.put(EmailTask(template, subject, context))



    async def run_queue_worker(self):

        '''Background task — processes email queue'''

        while True:

            task = await self.queue.get()

            if self.rate_limiter.allow():

                html = self._render(task.template, task.context)

                await self._send_smtp(task.subject, html)

            self.queue.task_done()



    async def _send_smtp(self, subject: str, html: str):

        msg = MIMEMultipart('alternative')

        msg['Subject'] = subject

        msg['From']    = self.username

        msg['To']      = self.recipient

        msg.attach(MIMEText(html, 'html'))

        async with aiosmtplib.SMTP(self.smtp_host, self.smtp_port) as s:

            await s.starttls()

            await s.login(self.username, self.password)

            await s.send_message(msg)

5. Personal Use — Architecture Simplifications

Because this bot is used exclusively by one person, several architectural components can be drastically simplified compared to a multi-user or commercial system. This reduces complexity, maintenance burden, and attack surface.



5.1 Authentication — Simple Static Token

There is no user database, no OAuth, no JWT login flow for the dashboard. Authentication is a single static Bearer token stored in .env:

# .env

DASHBOARD_TOKEN=your-long-random-secret-token-here



# Frontend (.env.local)

VITE_DASHBOARD_TOKEN=your-long-random-secret-token-here



The backend validates this token on every API request and on WebSocket connection.

The React frontend reads the token from its .env.local and sends it as a Bearer header on all API calls.

Since this runs locally or on your personal VPS, the security model is: control network access (VPN or SSH tunnel) + static token. No need for OAuth 2.0 complexity.

To access the dashboard remotely, use SSH port forwarding: ssh -L 5173:localhost:5173 your-vps which tunnels the frontend to your local machine securely.
